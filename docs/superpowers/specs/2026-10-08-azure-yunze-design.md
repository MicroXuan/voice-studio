# Azure 云泽语音接入设计

## 目标

在现有“声屿 Voice Studio”本地文本转语音网站中增加“云泽”男声。云泽通过 Azure Speech REST API 合成，现有云健、云希、云夏、云扬和晓晓继续通过 Edge TTS 合成。用户仍使用同一套文本输入、参数调整、任务进度、试听和 MP3 下载流程。

本阶段面向本地个人使用。常见输入为几千字，继续沿用现有最多 20,000 字的限制。

## 非目标

- 不把 Azure 密钥发送到浏览器或保存在前端。
- 不提供在线用户注册、多人配额、计费或部署功能。
- 不迁移现有 Edge 声音到 Azure。
- 不引入 Azure Speech SDK；当前只需要一次文本转语音 REST 调用。
- 不为 Azure 返回伪造的逐字精确进度。

## 用户体验

声音列表新增“云泽”，声音 ID 为 `zh-CN-YunzeNeural`，并明确标注由 Azure 提供。

当 `AZURE_SPEECH_KEY` 和 `AZURE_SPEECH_REGION` 均已配置时，云泽可正常选择。未配置时，云泽仍显示，但卡片不可选择，并显示“需配置 Azure Speech”。其他声音的可用性和行为不受影响。

选择云泽后，用户仍按现有方式输入文本、调整语速、音调和音量、创建任务、试听结果并下载 MP3。Azure 合成期间使用阶段式状态，例如“正在连接 Azure”“正在合成语音”“正在保存音频”。

## 配置与安全

本地配置使用以下环境变量：

- `AZURE_SPEECH_KEY`：Azure Speech 资源的 Key 1 或 Key 2。
- `AZURE_SPEECH_REGION`：Azure 资源区域，本项目当前为 `eastasia`。

项目提供不含真实值的 `.env.example`，真实 `.env` 加入 `.gitignore`。应用启动时从本地环境读取配置。密钥不得：

- 写入源代码、测试夹具或文档；
- 通过任何 API 响应返回；
- 注入浏览器 JavaScript；
- 出现在正常日志或错误信息中。

Azure 的完整错误响应不直接展示给用户。认证和服务错误映射为安全的中文信息。

## 架构

### 声音元数据

扩展 `VoiceOption`，为声音声明服务提供方、可用状态和不可用原因。静态声音目录记录每个声音应由 `edge` 还是 `azure` 提供；运行时根据 Azure 配置计算云泽的可用状态。

`GET /api/voices` 返回适合前端展示的声音列表，但不返回任何凭据。

### 统一合成入口

应用使用一个统一的合成路由器。路由器接收现有的合成参数，根据声音元数据选择服务：

- `edge` 声音调用现有 `EdgeTTSService`；
- `azure` 声音调用新增 `AzureTTSService`。

路由决定保留在后端，前端不需要知道服务端调用地址或认证方式。创建任务前，API 同时验证声音存在且当前可用。对不可用的云泽返回可理解的验证错误，即使客户端绕过了禁用状态也不会发起 Azure 请求。

### Azure REST 客户端

`AzureTTSService` 使用项目已有的 `aiohttp` 发送异步 HTTPS 请求，不增加 Azure SDK 依赖。请求目标由区域构造为该区域的 Speech 合成端点，认证信息只放在请求头中。

服务将用户文本构造成 XML 安全的 SSML，使用 `zh-CN-YunzeNeural`，并把现有整数参数映射到 Azure prosody：

- 语速：带正负号的百分比；
- 音调：带正负号的百分比；
- 音量：带正负号的百分比。

请求输出格式为 MP3。响应先写入与现有实现一致的 `.part` 临时文件；只有收到非空音频后才原子替换最终文件。取消或失败时清理临时文件。

## 数据流

1. 浏览器请求 `/api/voices`，渲染所有声音及其可用状态。
2. 用户选择声音并提交现有 `POST /api/jobs` 请求。
3. API 验证声音存在且可用，创建后台任务。
4. 合成路由器根据声音提供方调用 Edge 或 Azure 服务。
5. 服务通过现有回调更新任务进度和阶段消息。
6. 成功时任务指向生成的 MP3；浏览器沿用现有试听和下载接口。
7. 失败时任务保存安全、可操作的中文错误，临时文件被清理。

## 错误处理

错误按用户可采取的操作分类：

- 未配置凭据：云泽禁用；直接提交时提示“需配置 Azure Speech”。
- 认证或区域错误：提示“Azure Speech 配置无效，请检查 Key 和 Region”。
- HTTP 429 或配额相关响应：提示“Azure 免费额度可能已用完或请求过于频繁，请稍后重试”。
- Azure 其他服务错误：提示“Azure 语音服务暂时不可用，请稍后重试”。
- 网络或超时：提示检查网络后重试。
- 空响应：提示服务没有返回有效音频。
- 文件写入失败：提示检查磁盘空间或临时目录权限。

日志可以记录状态码和错误类别，但不得记录认证请求头、Key、完整请求对象或包含敏感内容的响应。

## 前端变更

声音卡片识别 `available` 和 `unavailable_reason`：

- 可用声音保持当前交互；
- 不可用声音显示禁用样式，不能被键盘或鼠标选中；
- 云泽显示 Azure 标识和配置提示；
- 如果当前选中的声音因列表刷新而不可用，前端自动选择第一个可用声音。

现有生成、轮询、播放器和下载逻辑保持不变。

## 测试策略

自动测试使用假 HTTP 会话和假合成服务，不使用真实 Azure Key，也不产生实际 Azure 用量。

覆盖范围包括：

- 声音元数据和 Azure 配置存在/缺失时的可用状态；
- Edge 与 Azure 路由选择；
- SSML 对文本和属性的安全转义；
- 语速、音调、音量映射；
- Azure 成功响应、空音频、认证失败、限额、服务错误、网络异常和写入失败；
- 失败和取消后的 `.part` 文件清理；
- `/api/voices` 不泄露配置且返回正确可用状态；
- 不可用云泽不能创建任务；
- 前端禁用状态和 Azure 标识；
- 现有 Edge TTS 回归测试继续通过。

自动测试通过后，使用本机 `.env` 中的凭据进行一次短文本真实试听，确认云泽能生成并播放 MP3。真实验证不得打印或提交 Key。

## 完成标准

- 配置有效时，云泽可以从现有页面生成、试听和下载非空 MP3。
- 未配置 Azure 时，网站仍可启动，云泽清楚地显示为不可用，所有 Edge 声音正常工作。
- Azure Key 不出现在版本库、浏览器、API 响应或日志中。
- Azure 与 Edge 的主要成功和失败路径均有自动测试，原有测试全部通过。
